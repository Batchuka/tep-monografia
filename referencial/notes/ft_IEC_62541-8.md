>O foco aqui é mais específico: como modelar variáveis industriais acessíveis por clientes — sensores, valores calculados, estados, diagnósticos, dados de dispositivos, etc. 
>
>A norma define o modelo de informação associado a esse acesso a dados, incluindo VariableTypes, propriedades, atributos e comportamentos adicionais necessários para representar corretamente esses valores no OPC UA.
>
>Não basta expor um número bruto. Um cliente industrial precisa saber se aquele valor é analógico, discreto, vetorial, qual sua unidade de engenharia, qual faixa normal, qual faixa do instrumento, qual precisão, se o valor é confiável, se a semântica mudou e quando uma mudança deve ser reportada. 
>
>A proposta central é formalizar o conceito de DataItem: um nó que liga o AddressSpace do OPC UA a dados vivos de automação. A partir dele derivam tipos como AnalogItemType, DiscreteItemType e ArrayItemType.
